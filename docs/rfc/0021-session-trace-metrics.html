A plain-HTML prototype of §4.5 (the UI) and §4.2 (the TraceMetrics contract). The only data source is a real capture — conversation-1671-trace.csv, 140 entries exported read-only from the sandbox's session.sqlite — embedded below and folded by a JavaScript traceMetricsOf that mirrors the RFC's projection field by field.

§0

How to read this prototype

  • Every number in the two app panels is computed in your browser from the embedded CSV — nothing is hardcoded, nothing calls the sandbox. View source: the CSV is the <script type="text/csv"> block, the projection is traceMetricsOf() at the end of the file.
  • The limit selector inside the first panel is the RFC's central demo (V6): it changes the page you see, never the metrics. Metrics always describe the newest-500 window (§4.3).
  • Two things the CSV cannot answer, by construction of an entries export: per-run judge states and citation run states. They live in separate documents read through TraceSource.runState(). The prototype renders exactly what the RFC prescribes for that case: judge: null, and a citations block where missing state is a count, not a silent skip.

Trace detail — what the page renders from report.metrics

The RFC 4.5 detail page: five cards and the tool table read metrics instead of recomputing summarizeDecisions in the browser (R1, R7). The Errors card carries the three classes of errors.total. The ledger is the conversation's own, not the agent's (R3).

Defect → where this page shows the fix

		

			
Defect / checkWhat this prototype renders

			
R1 · four aggregatorsOne projection (traceMetricsOf) feeds the cards, the tool table, the index columns and the artifact. No browser-side aggregation exists here.

			
R2 / V5 · invisible windowThe dashed banner names the window: bounds, entry count, complete flag. 140 ≤ 500, so it says "the window is the conversation".

			
V6 · limit-independenceThe ?limit= selector re-slices only the entries page; every metric stays identical. Try it.

			
R3 · agent-wide usageThe ledger row is summed from this conversation's assistant messages only — the fix of §4.4 (UsageDoc per conversation).

			
R6 · dropped model errors9 of 57 responses ended stopReason: "error": they are in errors.model and in the stop-reason bars; the messages themselves stay behind /entry (the collapsed list above).

			
R4 · judge aggregationjudge: null — no run state is reachable from an entries export; the real reader folds every attempt into all vs shipped.

			
R5 · citation scalarcitations.runs = 2 with missingState = 2: missing state is a count, not a silent skip (§4.2).

			
R7 · not an artifact§3 prints the exact object the capture would store.

			
R8 · index wakes sandboxThe index panel reads stored numbers only; no live citations card.

			
calls ≠ resultsThe tool table shows answer_publish with 25 calls / 25 results / 24 errors — mostly citation-gate rejections, visible as friction instead of disappearing between two disagreeing totals.
