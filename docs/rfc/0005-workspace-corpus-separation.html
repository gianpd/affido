The workspace is scratch. The corpus is durable shared knowledge. This is the separation, the two phases it creates, and who owns what after it.

01

The problem: one directory, two incompatible jobs

Today the corpus is corpus/raw/ inside the sandbox workspace

The upload path and the retrieval path both go through the sandbox volume. That is fine for a handful of documents and breaks on every axis that the product needs next: sharing, durability, size, and retrieval quality.

↑ ingest and retrieval share one medium, so the corpus inherits every limit of the sandbox volume.

lifecycle

Uploading requires a live sandbox

A 660 s synchronous parse keeps the sandbox active, so a single ingest defeats idle pause. Two hundred uploads pin one container for hours.

limits

Three limits that do not agree

Browser cap 10 MiB, parser cap 50 MB, workspace volume finite and per user. The smallest of the three decides the product.

retrieval

Retrieval is ls plus read

At 100 documents the model cannot tell which ones matter. Context fills with file listings and full text. At 105 documents the listing is useless and the bucket walk is O(N) head requests.

durability

Nothing survives the sandbox

No versioning, no citation pinned to a version, no sharing between sandboxes, no way for a new sandbox to read the old corpus. The knowledge dies with the volume.

One sentence: the corpus is not a file in a container. It is a catalog plus immutable objects with a different lifetime than the process that reads them.

02

The assumptions the design rests on

Each one is load-bearing: remove it and a specific guarantee disappears

These are not goals. They are the beliefs that make a five-tool facade, a Postgres catalog and a content-addressed bucket sufficient. The last column is what breaks if the assumption is false.

#AssumptionWhy it is believedIf it is false
A1 Workspace and corpus have different lifetimes and different access rules. Workspace is scratch for one sandbox; corpus is shared, must survive stop, recreation and host change. Keep one directory: no sharing, no versioning, capacity bounded by the volume.
A2 The model needs domain verbs, not a storage protocol. Five tools fit under 4 KB of JSON Schema; the 17 raw storage tools cost about 3k prompt tokens per turn. Expose the raw plane: opId, ifVersion, branch, merge leak into the model.
A3 Sources are immutable, derived text is deterministic, agent records are append-only, only the canonical page is mutable. Most writes never touch a shared key, so independent agents cannot conflict. N writers on one document: merge becomes the product, and the merge is not free.
A4 Content addressing makes idempotency free. The key names the hash, so the same bytes converge on the same object. A cache key is the hash. Every caller reimplements dedupe and retry; a retried upload becomes a duplicate document.
A5 Ingest is a control-plane job, not a sandbox request. The parser is an async worker; a 660 s parse must not pin a user's container. Upload wakes the sandbox and defeats idle pause; the browser limit becomes a technical constant.
A6 The catalog is the index; the bucket is never the catalog. Postgres full-text returns a bounded top-k. list(detail:"heads") is one head GET per key. corpus_search degrades to bucket enumeration, O(N), and the answer set is unbounded.
A7 The sandbox never holds bucket bytes or bucket credentials. No FUSE, no NFS, no synced directory. A tool call is the only path, so every access is attributable. bash can read the credentials; every agent reimplements the protocol; ACL is unenforceable.
A8 Reproducibility comes from versions pinned in the catalog. (docId, sourceSha256, parserVersion, labelSetVersion) makes ingest idempotent and citations auditable. Audit cannot tell a verified citation from a stale one; a parser upgrade silently rewrites evidence.

Explicit non-goals that follow from the assumptions: no vector search or RAG yet, no semantic merge inside the storage layer, no cross-corpus transactions, no general-purpose file browser over the bucket, no replacing the session database with the corpus.

03

The proposed solution: three planes, five tools, one port

Bytes leave the workspace; the model never learns the storage protocol
workspace · scratch

/workspace

Per sandbox, on a volume, disposable. Coding tools: read, write, edit, bash. Charts, unpacked archives, intermediate files.

Dies with the sandbox. That is correct.

corpus · durable

Object storage + catalog

Shared, versioned, survives stop, recreation and host change. Reached only through corpus_*. Postgres holds ownership, roles, hashes, status, search index.

Outlives every sandbox that reads it.

session · unchanged

/data/session.sqlite

The conversation, on the data volume, managed by the pi-durable Harness. Open, resume and pause stay serialized on one promise chain.

Not touched by this RFC.

Target: five tools under 4 KB of JSON Schema. No capabilities, head, write, branch, merge, put_blob, get_blob, leases.

object layout

Content-addressed, immutable

<tenant>/corpus/<id>/<doc>/source/<sha>.ext
<tenant>/corpus/<id>/<doc>/text/<sha>.md
<tenant>/corpus/<id>/<doc>/entities/<sha>.json
<tenant>/corpus/<id>/<doc>/records/<author>/<id>.json
<tenant>/corpus/<id>/<doc>/knowledge/<version>.md

One mutable pointer: the knowledge/head row in Postgres, updated in a transaction with a version precondition.

write protocol

Three paths, three guarantees

1 · source ingest — immutable. The presigned PUT writes the source object; POST /corpus/ingest verifies it, recomputes sourceSha256, and is idempotent by (docId, sourceSha256, parserVersion, labelSetVersion); a different hash on the same docId is 409.

2 · agent annotation — append-only record under records/<author>/. No shared key, no conflict.

3 · canonical publish — optimistic concurrency on baseVersion. A stale base returns stale_base plus the current version and writes nothing.

Storage stays an implementation detail behind the CorpusStore port (putSource, putText, getText, putRecord, getHead, compareAndSetHead, signUpload). Baseline: bucket + Postgres. Casplane: optional backend when same-key branches and merge lineage are required. The tool contract is identical, and an in-memory fake runs the five tools with no database and no network.

No edge from the sandbox to object storage

No FUSE mount, no NFS, no synced directory, no S3 SDK. Bytes are reached only by a tool call, which is what makes every access attributable and keeps credentials out of a container where bash can read them.

drawn as a container on purpose

The control plane is a contract, not a deployment

Today the /corpus/* routes can live in the SvelteKit server. The rectangle exists because the control plane owns keys, ACL, versions and hashes; it can split into its own service without changing the five tools or the agent.

05

Two phases that must not be confused

Ingest never touches the sandbox; retrieval never touches the bucket directly

The split is what buys the guarantees: an upload is a control-plane operation with its own worker, a question is a sandbox operation that calls a bounded tool. The right-hand column of each lane is the state of the sandbox at that step.

Phase A · Ingest

bytes → objects → text → catalog sandbox: cold, stays cold
  1. 1
    Browser asks for a place to put the file POST /u/<u>/corpus/uploads {corpusId, docId, filename, bytes, sha256?}

    The UI sends intent, not necessarily the bytes. A small file may stream directly in the same call.

    cold
  2. 2
    The control plane signs the upload 201 { uploadUrl, key, expiresAt }

    Presigned PUT for large sources. The control plane never buffers the body, so a 40 MB PDF does not pass through it.

    cold
  3. 3
    Bytes go straight to object storage PUT <uploadUrl>

    The browser has a scoped, expiring URL. It has no list, read or delete permission on the bucket.

    bucket
  4. 4
    The browser declares the upload finished POST /corpus/ingest {corpusId, docId, sourceKey, sourceSha256}

    The server verifies the object and recomputes the hash. A supplied hash is a hint, never the truth.

    cold
  5. 5
    The catalog row exists before the text does 202 { ingestId, status: "parsing" }

    The document is visible as parsing. corpus_search hides it unless the model asks for that status explicitly, so a half-ingested document is never evidence.

    cold
  6. 6
    The knowledge converter parses, off the request path source → text + entities · parserVersion pinned

    A worker, not a route in the sandbox. The 660 s parse budget costs a worker minute instead of pinning a user's container.

    cold
  7. 7
    Derived objects are written text/<textSha>.md · entities/<textSha>.json

    Content-addressed, so the same parse of the same source under the same parser version converges on the same object.

    bucket
  8. 8
    The document becomes searchable status: ready · textVersion · textSha256 · FTS row

    Idempotent by (docId, sourceSha256, parserVersion, labelSetVersion). Same docId with a different hash is 409, not an overwrite.

    ready
Cost of the phase: the sandbox is never started. Two hundred uploads leave the container stopped, so idle pause keeps working and per-user cost stays at storage plus requests.

Phase B · Prompt and retrieval

question → bounded window → verified citation → page sandbox: woken, then paused again
  1. 1
    The question arrives POST /u/<u>/prompt { requestId, message }

    Same requestId returns the admitted submission instead of running a second one. This is unchanged by the RFC.

    cold
  2. 2
    Caddy resolves the user to a sandbox forward_auth GET /resolve?user_id → X-Sandbox-Endpoint

    The manager creates or starts the container and returns its upstream. A client-supplied endpoint header is stripped before the dial.

    waking
  3. 3
    The harness resumes the same conversation Harness.activate → open / resume / #syncAgent

    SQLite at /data/session.sqlite on the data volume. A provider or thinking-level change rewrites the stored agent config; it does not wipe the session.

    awake
  4. 4
    The model finds candidates without reading them corpus_search { corpusId, query, docIds?, labels?, limit ≤ 20 }

    Postgres full-text or trigram, returning snippets of at most 400 characters. Never a bucket listing. docIds is intersected with the caller's ACL; an unauthorized id is omitted, not leaked.

    awake
  5. 5
    The model reads a window, not a document corpus_read { docId, version, needle | lineRange, maxChars }

    At most 16 KB by default, absolute code-point offsets computed by the server, an explicit truncated and next. A bare call returns a table of contents or an error.

    awake
  6. 6
    Contributions are append-only, the page is single-writer corpus_annotate → record + citation · corpus_publish → knowledge/<v+1>

    The server re-reads the version, recomputes textSha256 and checks the exact slice: hash_mismatch, out_of_bounds, quote_mismatch. Publish with a stale baseVersion returns stale_base and writes nothing.

    awake
  7. 7
    The answer streams; the evidence stays auditable citation rows in the catalog · session stream to the browser

    The conversation remains in SQLite. The citation rows live in the catalog, so GET /corpus/citations?runId=… can verify the same run from any sandbox, after a restart, without calling a model.

    pauses when idle
Cost of the phase: the sandbox is awake only while the conversation runs. The corpus is read through the control plane, so a new sandbox with an empty workspace still sees every document and every citation.

Why keep them apart: ingest is long, retryable and user-independent; retrieval is short, interactive and conversation-bound. One shared medium forces the container lifetime of the second onto the work of the first.

06

Who does what

Four actors, four jobs, four things each one is not allowed to do

Client

browser + frontend · uploads and asks
Owns
  • the user intent: this file, this corpus, this question
  • the presigned PUT: bytes go from the browser to the bucket
  • the requestId of a prompt and the streamed answer
  • presentation of status, citations and stale_base recovery
Refuses
  • holding bucket credentials or list/delete rights
  • parsing, chunking or computing offsets
  • being the place where ingest blocks
  • deciding what the corpus contains
Artifacts
an upload intent, a prompt, a rendered answer.

Knowledge converter

parser worker · source becomes text
Owns
  • the parse: source bytes → text plus entities
  • parserVersion, and therefore text reproducibility
  • the async worker pool and its 660 s budget
  • the parsing → ready | failed transition
Refuses
  • writing the bucket or any catalog row
  • owning ACL, roles or quotas
  • minting citations or verifying slices
  • answering a user request
Artifacts
text + entities bytes and a parserVersion, returned to the control plane. No key, no row.

Data control plane

/corpus/* + CorpusStore + catalog
Owns
  • keys, versions, hashes, and the knowledge/head compare-and-set
  • ACL: corpus membership, roles, tenancy, quotas
  • the search index and the bounded result shape
  • citation verification and retention pinning
  • idempotency, retries, orphan reconciliation
Refuses
  • running a model or generating text
  • deciding which evidence matters
  • letting the sandbox mount or sign its own upload
  • trusting a hash or offset supplied by the model
Artifacts
catalog rows, object keys, citation status, presigned URLs.

Agent sandbox

pi-durable agent · the only reader
Owns
  • the conversation, in /data/session.sqlite
  • the scratch workspace and coding tools
  • the decision of what to search, read and cite
  • composing the answer, and recovering from stale_base
Refuses
  • seeing object keys, blob hashes or branch ids
  • reaching the corpus with bash, ls or read
  • holding bucket credentials
  • publishing without a baseVersion
Artifacts
tool calls, records, a publish request, the resumed session.

the seams

Only two contracts can leak

control plane → converter: source key plus hash in, text bytes plus parserVersion out. The converter sees content, never ACL, credentials or a key to mint.

sandbox → control plane: five tools, no keys. If this seam ever grows a write, a head or a branch, the RFC has been undone.

the failure story

Every actor can be restarted alone

The converter can re-run: ingest is idempotent by hash and parser version. The control plane can restart: it is stateless and the catalog holds the truth. The sandbox can stop: the session is on a volume and the corpus never was. The browser can close: the run continues, citations are in the catalog.

07

What the separation must not break

Existing durability invariants that survive the RFC unchanged
session stays
SQLite at /data/session.sqlite, on the data volume. The corpus is more durable than the sandbox, not a replacement for the session.
probing stays free
GET /health and GET /status never open storage. The new catalog is not touched by a probe, or idle pause dies.
prompt stays idempotent
Same requestId, same admitted submission. No second run, no matter which sandbox serves it.
lifecycle stays serialized
Open, resume and pause on one promise chain inside DurableHarness. Routes and tools go through Harness.activate.
paths stay confined
Workspace paths stay inside WORKSPACE through NodeExecutionEnv. Corpus paths simply stop existing there.
routes stay declared
Every new route is an HttpTool and declares whether it activates the agent. /corpus/* routes do not.
rotation stays cheap
Changing provider or model must not wipe a session. #syncAgent rewrites pi.agent; thinking level follows THINKING_LEVEL.
topology stays a manager job
Sandboxes are created by create_args in the manager, not by compose. Corpus topology follows the same rule.
Spot checkPass condition
No bytes in the workspacebash find /workspace -name '*.pdf' returns nothing for uploads; bash cannot read a corpus document.
Cold stays coldA stopped sandbox stays stopped while POST /corpus/uploads and POST /corpus/ingest complete and Postgres reaches ready.
No bucket listing104 documents, bounded result, bounded p95. corpus_search queries Postgres.
Offsets are exactASCII, accented and astral text return exact code-point start/end and an exact slice.
Bad evidence is refusedA wrong slice, an out-of-bounds span or a stale hash writes no record: quote_mismatch, out_of_bounds, hash_mismatch.
No lost updateTwo publishes on one baseVersion: one succeeds, one gets stale_base with the actual version.
Audit never liesAfter restart and past KeepVersions, a citation is attribution_verified or version_unavailable. Never a false pass.

The decision requested: approve the separation and the five-tool facade as the target design; approve the baseline backend (object storage + Postgres catalog + immutable content-addressed objects); defer the casplane-versus-bucket choice to a one-week spike behind the CorpusStore port. The tool contract does not change with the backend.
