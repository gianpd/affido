Comparative analysis · RFC 0017 / RFC 0018 LAQuer, ACL 2025 long · pp. 15355–15370 2026-11-24

The same pair, two questions. One measures attribution; the other enforces it.

The zero-shot judge eval asks whether a quote can be attached to a line that misstates it. LAQuer asks whether the attributed span is enough for a claim the user just highlighted. Both read the same object — a (claim, evidence) pair — and neither number can be read as a score of the other.

1

Two experiments, one shared unit

one is a control at write time · the other a benchmark of attribution quality after the fact

Both systems put two texts side by side. The judge eval takes a published line and the verified quote stored behind its cit_… id, and asks a three-way decision question. LAQuer takes an output span the user highlighted, rewrites it to stand alone, and asks which source spans entail it. The first is a gate's second opinion; the second is a task definition with a metric attached. That difference of purpose drives every row in §2.

Operative differences, one axis per row

the blue rows are the ones that decide whether a number from one system can score the other
AxisafFido · zero-shot judge eval (RFC 0017/0018)LAQuer · ACL 2025
Who initiates The server, while a publish is being checked. The user's only lever is the per-submission toggle. The user, after reading, by highlighting an output span. The method must serve a query the system could not anticipate.
When Generation time, after the deterministic gate of RFC 0006 accepts and before the publish exists. Post-hoc, on outputs produced by other systems, including unattributed ones.
Unit One (published line, verified quote) pair, per cited id. One highlighted output span, against candidate source spans.
What is compared The line with tokens stripped vs the quote the annotation already stored. The decontextualized output span vs spans the attributor found in the source.
Decontextualization Absent. Whatever anaphora the line carries stays in the claim, so a faithful quote about a self-contained fact passes even when the line leans on a previous one. Mandatory step (A): pronouns and elided referents are rewritten into a standalone statement before attribution.
Output One verdict per pair (supported, unsupported, contradicted) plus a score. Source spans s₁…sₘ plus an entailment score from a separate NLI model.
Decision rule Argmax, no threshold; per line, at least one supported and no contradicted. enforce rejects and the model retries. No decision rule. The score is aggregated and reported; nothing is refused.
Failure policy Fail closed: deterministic checks first, then the judge. Nothing is written on rejection, and a judge that cannot run is skipped rather than faked. Degrade: fuzzy match → retry ×5 → generation metadata → all source documents.
Supervision Zero-shot, typed-choice question with one neutral definition per label. No fine-tuning. Task definition plus prompts; LLM-internals baseline needs an 8B model on one A100 for ≈8 h, after the paper's negative result on hidden-state alignment.
What it is scored against 74 hand-labeled pairs (41 Italian), 44 dev / 30 test; held-out test has 14 supported and 16 unrelated-or-contradicted. MDS and LFQA, contextualized and decontextualized, with an NLI judge (AutoAIS, T5-xxl).
Cost One decision call per pair (~138 input tokens, ~$0.000003, p50 217 ms); local GLiNER alternative at ≈930 MB RSS and 228 ms. One extra LLM call per query, or the 8B internals run.
Audit Durable run state: verdicts, scores, truncations, errors, p50/p95 in the run report, re-verifiable after restart. A benchmark. No durable per-query audit, no idempotent replay.

The blue rows are the ones where the two systems answer different questions: write-time control vs post-hoc measurement. A metric from one cannot score the other.

The honest comparison: 1.00 and 58.0 are not two readings of the same quantity. One is classification accuracy on a hand-labelled pair set; the other is an entailment score on an end task whose input was deliberately decontextualized. Subtracting them, or calling one "better", would be a category error.

The same line, through the shipped layer

// answer_publish — deterministic gate passes, then one decision call per id evaluatePublish({ markdown, declared, annotations, runId }) → { ok: true } // every line cited, ids verified, same run coherenceOf({ markdown, quoteOf, judge }) // line 4: claim = "L'assistenza è inclusa nel canone annuo" // quote = "La disdetta deve essere comunicata 90 giorni prima." → verdict "unsupported" score 0.94 ms 213 // enforce → nothing written, the model retries with the right quote { "status": "rejected", "reason": "incoherent_citation", "detail": "line 4: L'assistenza è inclusa… [cit_9f2a] not supported by any cited quote" }

The retry is the point. A rejection is not a failed answer; it is a line that has to be re-cited. In warn the verdicts are recorded and the publish goes through, which is useful for observability and useful for comparing judges — not for enforcement.

5

The six gaps, after the judge

what RFC 0018 closed, what it only narrowed, and what still belongs to the paper

The judge eval is not a general answer to LAQuer. It closes one channel — the claim that a line states something the quote does not — and leaves five. Mapping them one by one is the only honest way to say what changed in the product.

Gap (from RFC 0006)Before the judgeWith enforceStatusWho could close it
M1 · sufficiency A verified quote can be useless on its own. The line is checked against the quote, not the quote against the world. A faithful, self-contained quote about a different fact still passes. open LAQuer's decontextualization step, ported as a lint.
M2 · minimality Cite the entire document: still verified, under MAX_QUOTE_CHARS = 1000. Unchanged. The judge truncates its own input at 1400 characters; the gate's 1000-character cap is untouched. open Sentence-level cap, plus attributed characters in the report.
M3 · post-hoc query A free-run answer has no span map. Unchanged: citations exist only for strict runs. open An RFC: persisted token positions plus a route outside /prompt.
M4 · line granularity Two facts, one sentence, two sources; the token position is asserted. Every cited id is judged against the line, and a contradiction on any id fails the line. Position is still asserted, not verified. narrowed Claim-level spans, which needs the model to cite clauses, not lines.
M5 · the user's lever All lines or nothing. Unchanged, and enforce adds a second all-or-nothing layer: a single incoherent line blocks the publish. open A per-claim citation policy, not a per-run flag.
M6 · the metric citationExactness cannot see an insufficient attribution. The run report now carries supported / unsupported / contradicted counts, truncations, errors, p50/p95. citationExactness itself is unchanged. narrowed Report attributed characters per citation next to exactness, as the paper does.

The asymmetry in one line: the judge makes the contradiction channel enforceable at write time; LAQuer makes the sufficiency channel measurable after the fact. A product that needs both runs both — one is a gate, the other a score.

closed by the judge

Wrong-clause and negation citations. 0 false accepts on 16 unrelated-or-contradicted pairs, 0 false rejects on 14 supported ones, against a fixed bar.

narrowed

Line granularity and the metric. Per-id verdicts and per-run counters exist; position is still model-asserted and exactness still cannot see insufficiency.

still open

Sufficiency, minimality, post-hoc queries, per-claim levers. None of them is a judge problem; each needs a different mechanism.

6

What each side would import from the other

a concrete list, not a synthesis
afFido ← LAQuer

Four things worth taking

1 · Decontextualization lint. Flag a quote that leans on an unresolved anaphor or comparative while its referent sits outside the quote. Lexical heuristic, no model, no gate change — the reader gets the warning the judge cannot produce.

2 · Minimality bound. Cap a quote at the sentence that contains the match instead of 1000 characters, and report attributed characters per published citation next to citationExactness.

3 · The sufficiency label in the UI. The Files-used panel should say "faithful to the quote" and "self-contained" separately, because they are different properties and only the first is enforced.

4 · A post-hoc span query. Persist token positions per message and expose a route that can call corpus_annotate outside a submission. This is the paper's task, and it is an RFC, not a flag.

LAQuer ← afFido

Three things the paper does not have

1 · Fail-closed attribution. A span that cannot be located exactly is not "degraded" — it never becomes a citation. Forged quotes have no path into the pipeline at all.

2 · A write-time decision. The judge rejects before the reply is fixed, and the model retries. The paper's objective is measured after the answer exists; nothing refuses it.

3 · Durable per-run audit. Exact ids, offsets, textSha256, verdicts, truncations, p50/p95 — re-verifiable after a restart, idempotent on replay. A benchmark has no counterpart for this.

What neither imports: the other's metric as a gate. citationExactness is bookkeeping; AutoAIS is entailment. Neither turns into an enforcement rule by lowering a threshold, which is exactly why the judge layer is a separate mechanism and not a stricter evaluatePublish.

7

Verdict

aligned, adjacent, and not the same question
Aligned by design
The pair is the unit. Both systems read a claim against the evidence behind it, not the answer as a whole. The judge eval adds the deterministic part the paper leaves out: the evidence must already be proved present, at a known offset, in a known version.
Aligned by finding
Small decision models are enough for the relation. The paper replaces an 8B internals baseline with a task-level attributor plus NLI. The eval replaces generation with one typed forward pass: 138 input tokens, no output, ~$0.000003 per pair, 0 false accepts and 0 false rejects on the held-out set.
Adjacent, not comparable
1.00 accuracy and 58.0 AutoAIS measure different things. One is a three-way classification on 30 hand-labelled contract pairs; the other is entailment on a decontextualized end task. The eval says the judge is deployable; it does not say the attribution is sufficient.
Deliberately out of scope
Reader length, post-hoc queries, per-claim levers. These belong to the paper's task and remain open in afFido. The judge narrowed M4 and M6 and left M1, M2, M3 and M5 untouched.
What would change the verdict
A decontextualization lint on the quote, not the claim. If a quote that leans on an out-of-quote referent were flagged at annotate time, the judge and the paper's objective would start to overlap — and the Files-used panel would stop showing an orphaned span without a label.
Operational status
The layer is shipped, not recommended on faith. CITATION_JUDGE=enforce by default with liquid/d1.1; off and warn remain; a run with no OpenRouter credential makes no judge call, so the keyless default stack is exactly RFC 0006. gliner stays selectable as the no-egress artifact.

The one-sentence summary: the judge eval proves a zero-shot decision model can enforce claim-vs-quote coherence at write time; LAQuer proves that decontextualized entailment is the right measure of attribution quality and that it collapses without the rewrite. afFido now has the first and still lacks the second.
