Comparative analysis · RFC 0006 LAQuer, ACL 2025 long · pp. 15355–15370 2026-11-03

Both find the span. Only one of them proves it — and neither asks the same question.

afFido's strict citations and the paper's LAQuer task both answer "where in the source does this claim come from?". They differ in who asks, when, about how much text, and what happens when the answer is bad.

1

Two pipelines, one difference of direction

one is a gate around generation · the other is a task after it

LAQuer assumes an answer already exists and the user points at a piece of it. afFido assumes nothing exists yet: the model must earn the right to print a line by declaring a quote the server can find. The paper's method is post-hoc and user-driven; ours is generation-time and model-driven. Everything else below follows from that.

Operative differences, one axis per row

the rows with a teal bar are the ones that change what the product can answer
AxisafFido · RFC 0006LAQuer · ACL 2025
Who initiates The model, while writing. The user only sets citations:"required" for the whole submission. The user, after reading, by highlighting any output span. The method must serve a query the system could not anticipate.
When Generation time. Nothing is published before the evidence exists. Post-hoc. Runs on outputs produced by other systems, including unattributed ones.
Unit of the query The whole reply: every non-heading, non-blank line. One span o₁…oₙ, from a single word to the full output.
Granularity of the check Line-level presence: the line must carry ≥1 [cit_…]. Token position is model-asserted, unchecked. Span-to-span alignment: the returned source spans must support the highlighted output span.
Verification Deterministic: indexOf over stored bytes, code-point span, textSha256 re-checked at every index build. No model in the loop. Model-produced alignment, fuzzy-matched (diff-match-patch), retried ×5. Quality measured later by an NLI model (AutoAIS, T5-xxl).
Failure policy Reject. quote_mismatch, uncited_line, foreign_citation — nothing is written, no id is minted. Degrade. Fuzzy match → retry → fall back to generation metadata → fall back to all source documents.
Decontextualization Absent. The quote is whatever the model copied. Step (A), mandatory: pronouns and elided referents are rewritten into a standalone statement, and extra output spans are added to the highlight.
Minimality Absent. Only a length cap: MAX_QUOTE_CHARS = 1000. The point of the task. Measured as characters of attributed text per fact (Table 6).
Sufficiency Explicit non-goal: "a citation proves attribution, not truth" (RFC 0006 §3.2). The objective: concat(s₁…sₘ) ⊨ I(o|o…), scored by entailment.
Persistence / audit Durable run state in SQLite, re-verifiable after restart (GET /corpus/citations), exactness recomputed from the trace with no judge. A benchmark. No durable per-run audit, no idempotent replay, no cross-restart re-verification.
Cost Corpus tool calls under a budget (48/run). Zero extra model calls. Extra LLM call per query, or an 8B model on one A100 for ≈8 h to run the internals baseline.

The teal-barred rows are not "better vs worse": they are the rows where the two systems answer different questions, so a metric from one cannot score the other.

3

Where we agree — and the paper is evidence for our choices

four design decisions RFC 0006 made, four results that support them
Agreement 1 · no similarity-based localizer

Hidden-state alignment loses badly

LAQuer's LLM-internals method scores 18.0 AutoAIS (contextualized) and 13.1 (decontextualized) on MDS, against 82.2 for plain generation. The best case for it is a 46.6 on LFQA on top of Attr.First — still far below the 83.0 of the prompt-based method.

RFC 0006 never locates a quote by similarity. It locates it by exact string equality and refuses when the string is absent. The paper's negative result is the empirical reason that is not a loss.

Agreement 2 · attribute during generation

Localized generation metadata is the best carrier

Attr.First wins the contextualized column in both tasks (80.3 MDS, 88.0 LFQA) and the paper's reading is that LAQuer "can leverage initially localized attributions provided by the generation method itself".

afFido goes further and makes the generation method be the attributor: there is no separate generation step to borrow metadata from. The model that writes is the model that must quote.

Agreement 3 · spans beat documents

The length argument is the same argument

Document-level attribution costs 4679.5 characters per fact; sentence-level 278.5; span-level 128.0. LAQuer cuts read length by two orders of magnitude over Vanilla/ALCE and 59% over Attr.First.

RFC 0006 caps an annotated quote at 1000 characters and points the "Files used" panel at a line, not a file. Same direction — but see §4, misalignment M2: 1000 ≫ 128.

Agreement 4 · attribution ≠ truth

Both separate "is it in the source" from "is it supported"

The paper keeps attribution quality (AutoAIS) apart from output quality (Rouge-L, BertScore, METEOR, BLEURT-20, MAUVE). RFC 0006 declares truth verification a non-goal outright.

The difference is where the second question lives: in the paper it is a scored metric; in afFido it is currently nowhere, which is misalignment M1.

A fifth, structural agreement: both refuse to let the model compute offsets. The paper's LLM emits span text and the pipeline locates it; corpus_annotate accepts only citation.text and the server returns start/end/line. A model-supplied hash or offset is ignored in both designs — R1 in RFC 0006 is the same instinct.

4

Where we are misaligned

six gaps, each with the code line that causes it
M1 · the gate certifies attribution, never sufficiency

A verified quote can be useless on its own

annotate() succeeds when document.text.indexOf(quote) !== -1. That is all. Nothing asks whether the span contains the referents a reader needs. LAQuer's desideratum 3 asks exactly that, and Table 4 shows the cost of skipping it: Attr.First drops from 80.3 → 58.0 (MDS) and 88.0 → 83.9 (LFQA) once facts are decontextualized.

This matters in our UI, not just in theory: the hover card and the Files used panel show quote alone, out of context. §5 example 2 is a live case.

M2 · no minimality

Cite the entire document: still "verified"

The only bound is MAX_QUOTE_CHARS = 1000. A model may annotate the whole file and publish against it, and the gate will accept. Executed: a 145-character whole-document annotation minted cit_f5271a3732 (span 0–145) and answer_publish returned {"ok":true}.

LAQuer's central measured quantity — attributed characters per fact — has no counterpart in our report. citationExactness is blind to it by construction.

M3 · strict mode cannot answer a post-hoc query

A free-run answer has no span map

Citations exist only for runs that went through answer_publish. A reply produced in a free run is a string; there is no stored mapping from its words to a source. The user cannot later ask "which document supports these two words?" — the question the paper is built around.

Closing this is not a patch: it needs token positions persisted per message plus a re-entry route that can call corpus_annotate outside a submission. It is an RFC, not a config flag.

M4 · line granularity flattens the paper's Figure-1 case

Two facts, one sentence, two sources

The paper's motivating example: one sentence contains a fact from nbcnews.com and another from statnews.com. Its gate equivalent needs per-span attribution.

Our gate checks lineCarriesToken() — the line carries some token. The model places [cit_a] next to the right clause, and it usually gets it right, but the position is asserted, not verified. Two tokens on one line is legal and both are accepted wherever they sit.

M5 · the user's lever is all-or-nothing

No "cite only this claim"

citations:"required" is per submission (RFC 0006 §5.9, correctly so — it beats a sandbox env var). But its granularity is the entire reply: every line must be provenanced or the run cannot exit through answer_publish.

LAQuer's desideratum 1 is that "it is not possible to predict a user's specific interests in advance". Our toggle predicts them exactly: all of them, every time, or none.

M6 · our metric cannot see the failure the paper measures

citationExactness = 1.0 while the attribution is insufficient

exact = set(reported) == set(used) over published runs. A run whose every quote is real-but-insufficient scores 1.0. The paper's headline failure mode — the decontextualized collapse — is invisible to this number.

This is not a bug in the metric: the metric measures the property RFC 0006 claims (no padding, no omission). It just does not measure the property the paper cares about.

The honest summary of the misalignment: RFC 0006 closes the forgery channel completely and leaves the relevance channel entirely open. LAQuer does the opposite — it optimises relevance and never refuses an attribution. A product that needs both has to run both, because neither one can be turned into the other by adjusting a threshold.

insufficient attribution

The disagreement is not a bug in either system. The document itself is context-dependent — line 5 leans on line 4. LAQuer is designed to detect exactly that and does; RFC 0006 is designed to detect forgery and does. Both verdicts are correct answers to different questions, and a user reading the Files used panel gets the second-hand version of the first problem without any label for it.

Reading the paper's numbers

Attr.First, MDS: 80.3 contextualized → 58.0 decontextualized. The 22-point drop is the price of removing the surrounding context, and it is the number that predicts example 2.

Reading our number

1.0 exactness is a statement about bookkeeping, not relevance. It will stay 1.0 for a corpus full of orphaned spans, because a real quote is always a real quote.

The gap in one line

Our gate makes a fabricated citation impossible and a low AutoAIS invisible — a real quote attached to a claim it does not support passes. LAQuer makes that visible and refuses nothing.

7

Verdict

what is aligned, what is not, and what it would cost to close it
Aligned by design
Span-level attribution, offsets computed server-side, no model-supplied hashes. The paper validates the architecture RFC 0006 already had, and its negative result on hidden-state alignment validates the choice of exact matching over fuzzy alignment.
Aligned by outcome
Reading length. Both replace "read the document" with "read the span". Ours is ~8× looser in the worst case (1000 vs 128 characters), same direction, weaker bound.
Misaligned, unfixable by config
Post-hoc queries. Our citations are a property of a submission, not of an answer. Answering "what supports these words?" on an existing reply needs persisted token positions and a route outside /prompt.
Misaligned, fixable cheaply
Decontextualization lint. A quote that leans on an unresolved anaphor or comparative while its referent sits outside the quote can be flagged by a lexical heuristic — no judge, no model. It would surface example 2 at the gate instead of leaving it to the reader. This is a warning, not the gate's property: the gate stays exactly as mechanical as it is.
Misaligned, fixable cheaply
Minimality bound. Cap a quote at the sentence that contains the match rather than 1000 characters, and report attributed characters per published citation next to citationExactness. Both are additions to an existing counter, not new mechanism.
Deliberately out of scope
Entailment. Requiring concat(s) ⊨ claim means judging the claim, which RFC 0006 §3.2 refuses on purpose: the gate must be mechanical and judge-free. Adopting LAQuer's objective would make the gate probabilistic and the property unmeasurable from the trace alone.

If only one thing is taken from the paper: refusing bad evidence and finding the right evidence are different problems with different proofs. afFido solved the first, exhaustively. The paper's contribution is that the second one has a measurable definition — and it is the one users actually experience when they hover a reference.
