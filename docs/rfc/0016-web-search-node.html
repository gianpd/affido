Web search is a node, not a tool inside the sandbox

One capability, one container, only the network legs it needs. The agent keeps its workspace and its database; the node keeps the only egress, and it cannot write anywhere.

System context

C4 level 1 · who talks to the platform, and to what

The platform is one black box. The only new external dependency is a self-hosted search stack; the internet is reached by that stack, never by the sandbox.

The search stack is the only component with a route to the open web. The sandbox reaches the internet only through it, and it writes nothing but HTTP responses.

2

Containers

C4 level 2 · one user's slice, both request paths

Three networks, one node on their boundary. The red box is the sandbox process: it owns /workspace and /data, so it is the thing a prompt injection can pollute. The violet node owns neither.

client control plane sandbox (attacker-reachable) web-search node (new) storage external / egress control call pair-internal call web call egress

Container boundaries are trust boundaries. The sandbox and the node share exactly one edge (9); the node and the search services share two (12, 13); only the services have a route to the open web (14).

Tool contract

the model never names a URL

Two model-facing tools, both thin HTTP clients over edge 9. The node resolves an opaque id to a URL from its own per-run table, so a page the model just read cannot become the next fetch target.

ToolCallReturnsBounds
web_search POST /search
{query, lang?, max?}		 [{sourceId, title, domain, snippet}] query ≤ 256 chars · ≤ 4 searches per run · ≤ 8 results
web_read POST /read
{sourceId}		 {untrusted:true, url, title, text, sha256} only ids issued to this run · 1 read per result · ≤ 6000 chars

Authorised per run. Web is off by default. The user enables it for one message with the composer toggle; the trusted admission path registers that run with the node using the manager-delivered control token, and stores the returned per-run token. The node refuses an unregistered run, a run registered with web: false, and any call without the matching per-run token (web_not_authorized). The model never writes the grant; a bash child cannot read the control token, so it cannot register a run of its own.

rejected by the node, every time
web_read {"url": "https://…"} → 400 no_url_in_arguments web_read {"sourceId": "web_other_run_3"} → 404 unknown_source web_read {"sourceId": "…/meta-data"} → the id is an opaque token, never a path web_search {"query": "…(12 KB base64)…"} → 413 query_too_long web_search 5th call in one run → 429 budget_exhausted * peer IP outside pi-net-<user> → 403 forbidden_peer

The node still has to fetch pages to read them, and it does that through Camofox, which lives on the egress network. The n2n fallback to a plain GET is dropped on purpose: a raw fetch inside the node would need egress in the node, and that is exactly what this topology removes.

Taint gate

what a poisoned page can still touch

Isolation bounds the blast radius; it does not stop the model from believing a page. Once a conversation has read web content, the harness blocks the tool calls that turn belief into persistence. The flag is derived from the durable trace, not stored as a mutable bit.

Tool classBefore web contentAfter the first web entry in the conversationWhy
read · bashallowedallowedNo egress in the sandbox; reading cannot persist anything.
write · edit → artifacts/allowedallowedThe deliverable. Verification stays with the citation gate.
write · edit → corpus/allowedblockedLaundering untrusted text into the trusted corpus makes it greppable and citable as if it were the user's document.
skills install · skills/*allowedblockedPersistence across runs. The highest-value target of an injected page.
connectors (RFC 0010)allowedblockedConfused-deputy send to a third party.
upload · ingestallowedblockedSame corpus argument, one layer up.
answer_publish · answer_plainallowedallowedCitations are verified against the stored page text, not the model's summary.
web_read from a URLneverneverNot a taint question: the tool has no URL argument at all.

Mechanism: hook(ToolTask, { beforeTool }), the same seam citation-tools.ts already uses to block write/edit on corpus paths during a strict run.

Workspace
The node writes nothing. No writable volume, so there is no path from a fetched page to the user's files except through the agent's own tools, which the gate above watches.
Egress
The node has no default route. Its only reachable peers are SearXNG and Camofox, so the capability is exactly "search and read", not "fetch anything".
Credentials
The Camofox bearer key lives in the node only (operator-supplied env, never a sandbox secret). It never enters the sandbox, and the model cannot ask the node to reveal it: no tool echoes it.
Cross-tenant
The node is dual-homed, so it rejects peers outside its own pi-net-<user> subnet. Another tenant's node on websearch-in is not a caller.

What this does not fix

name the channels, do not pretend they closed

residual · accepted or bounded

The query string is an exfiltration channel

200 bytes per search, and the node must forward them. Length caps and a per-run budget bound the rate; they do not close it. The implemented gate is the per-run authorisation of §5: web: "allowed" on /prompt, registered with the node through the manager-delivered control token. A hijacked model cannot start a search the user did not allow; a user who did allow web accepts this channel for that run.

inherent

Search results are adversarial by construction

Attacker-controlled pages are the normal case, not the edge case. The gate and the citation check reduce what a lie can achieve; they do not make a hostile page true.

shared infrastructure

SearXNG and Camofox are shared

One instance serves every tenant. Per-user sessionKey/userId, no shared cache, no shared history; a shared browser profile would leak pages across users.

by design

Poisoned history is not fixable

Hostile text stays in the durable conversation and compaction will re-read it. That is why the taint gate is conversation-scoped rather than run-scoped: waiting for the next prompt must not clear it.

Deletion test. Remove the node and put a fetch in the agent process: the sandbox needs egress, HTML parsing moves into the process that owns /workspace, and the only egress control in the diagram disappears. The node exists to keep edge 9 a narrow, id-only call and to keep egress in two containers that hold no user data.

Deviations, all inside the intent. The taint is a conversation-scoped durable document (web.taint) written by the first successful read, with a monotonic in-process cache; it is not re-derived from the transcript on every call, because the tool hook has no entry reader. The HTTP persistence routes therefore activate the agent on a cold cache (a restarted process) to read that document; /health and /status still never open storage. The node's health is not fatal on resolve, unlike the sidecar's: chat and uploads keep working while the search stack is down, and the tools answer search_unavailable. The node's peer guard is a CIDR list baked at create time, so a recreated per-user network recreates the node. Page text is document.body.innerText capped inside the browser (no Readability library in the image), not a readability extraction. websearch-in/websearch-out are created by the manager when absent (with --internal enforced on the former) instead of being purely operator-supplied; the services themselves remain operator infrastructure. The duplicate-read refusal is the named already_read; the RFC listed only budget_exhausted and unknown_source. The per-run web: "allowed" authorisation of §7 is implemented, and enforced at the node rather than only in the tool: the control token is derived from MANAGER_TOKEN, delivered to the node and the agent on every resolve, and held only in the agent's process memory, so a bash child cannot register a run. The control token is in-memory, not a mount; a changed MANAGER_TOKEN requires reprovisioning the node. Run authorisations expire after an hour.
