# Drift report — 2026-10-27

Scope: `README.md`, `frontend/README.md`, `marketplace/README.md`.
Method: every claim that names a file, route, field, environment variable or
command was checked against the current source. Only divergences are listed.

## README.md

- **Quickstart cannot start on the shipped default token.** `README.md:62` says `cp .env.example .env` and "the local default works". `.env.example:15` ships `MANAGER_TOKEN=dev-manager-token`; `dev.sh` generates a random token only when the line is *absent* (`dev.sh:106`), and `sandbox_manager.enforce_token_default` exits 1 on that exact value (`sandbox-manager/sandbox_manager.py:1840`). After the documented copy the manager crash-loops, so the quickstart's `curl .../u/dev-user/status` never succeeds. The workaround the code requires (`MANAGER_ALLOW_DEFAULT_TOKEN=1`) is not mentioned in the quickstart.
- **`POST /session/switch` is missing from the HTTP API table.** `README.md:279-287` describes it in prose and `agent/tools.ts:396` (`SwitchSessionTool`) implements it, but the table (lines 349-379) has no row for it.
- **`/session` and `/session/new` response models are incomplete.** The table documents `{ conversationId, entries }` (`README.md:353,377`); `ContainerAgent.session()` returns `{ agent, conversationId, entries, paused }` (`agent/agent.ts:340-350`) and `newSession()` returns `{ agent, conversationId, entries }` (`agent/agent.ts:354-357`).
- **`/status` response model is incomplete.** `README.md:352` lists `{ paused, conversationId, entries, inFlight, model, keyVia }`; `ContainerAgent.status()` also returns `agent`, `keyFingerprint`, `workspace`, `sessionDb` (`agent/agent.ts:134-147`).
- **`/prompt` response model is incomplete.** `README.md:374` lists `{ status, answer, evidence, citations[], artifacts[], submissionId, entries }`; the envelope also carries `agent`, `reason`, `reasonDetail`, `requestId`, `conversationId`, `evidenceReason`, `citationsMode`, `runId` (`agent/agent.ts:190-216`). `reasonDetail` and `evidenceReason` are the fields the chat UI renders, so they are not incidental.
- **`/ingest` "does not run the parser yet" is false** (`README.md:381-383`). `IngestPipeline` derives PDF text at staging time through `unpdf` (`agent/ingest.ts`: `derivePdfText` via `getDocumentProxy`/`extractText` at `:149`, admission `"derived"`, text written to `corpus/text/<docId>.txt`), which is what the very next paragraph, the `/text` row and RFC 0014 describe.
- **"the sole host mapping is Caddy's `18080:80`" is false.** `README.md:481-482` (architecture) claims it, but `docker-compose.yml:24` publishes Postgres on `127.0.0.1:${OLTP_PORT:-15432}:5432` — as the README itself states at line 154. The quickstart's "the only published port" (line 68) has the same problem.
- **`MANAGER_TOKEN` "required by every manager endpoint except `/healthz`" is false** (`README.md:201`). `GET /whoami` and all `/providers/*` methods authenticate by session cookie (or trusted-caller user id) and never consult the token: `providers_get` (`sandbox_manager.py:1622`), `read_user` (`:1555`), `write_user` (`:1540`). Two manager endpoints are also not documented anywhere: `GET /metrics` (`:1784`) and `POST /pause` (`:1829`).
- **`THINKING_LEVEL` never reaches a sandbox.** `README.md:295-299` promises that `#syncAgent` rewrites the stored thinking level when `THINKING_LEVEL` changes, so a reasoning-effort change takes effect without wiping the session. Nothing forwards it: `docker-compose.yml` has no `THINKING_LEVEL`, and `create_args()` passes only `AGENT_NAME`, `WORKSPACE`, `SESSION_DB`, `IDLE_MS`, `PORT`, `SIDECAR_URL`, `CITATIONS_DEFAULT` (`sandbox_manager.py:900-931`). `.env.example:112` and `dev.sh:322` advertise it as forwarded at create time. Only a standalone `docker run -e THINKING_LEVEL=...` reaches `server.ts`; in the manager stack the variable is inert, so the documented "change the level, keep the session" path does not exist.
- **`TraceSource` is described as "three read-only calls"** (`README.md:304`); the interface has four: `conversation`, `inspect`, `usage`, `runState` (`agent/trace.ts:127-135`).
- **"SvelteKit 5 app"** (`README.md:151`) — the dependency is `@sveltejs/kit ^3.0.0` with Svelte 5 (`frontend/package.json`); `frontend/README.md:9` states it correctly.
- **PRD 0003 is referenced three times but does not exist in the repo** (`README.md:363,385,615`, plus the same tag in agent/frontend source comments). There is no `docs/prd/` directory, so the normative source the `/uploads` contract points at is missing.

## frontend/README.md

- **"New session" is documented against the wrong route and the wrong semantics** (`frontend/README.md:134-138`). It says new session calls `/api/chat/reset`, which posts `/reset` and drops the `chat_message` rows. The UI's New session button calls `/api/chat/new-session` → `POST /session/new` (`frontend/src/routes/dashboard/chat/+page.svelte:136`, `src/lib/server/sandbox.ts:208-211`), and nothing is deleted: the previous conversation and its chat rows stay. `/api/chat/reset` still exists, but it is a separate action, not "New session".
- **Scope claims the agent cannot create conversations** (`frontend/README.md:184`): "One root conversation per sandbox… the agent does not create additional conversations yet." RFC 0008 is implemented end to end: `POST /session/new`, `POST /session/switch` (`agent/tools.ts:382,396`), `DurableHarness.newSession`/`switchSession` with a durable active-conversation pointer (`agent/harness.ts:122-168`), `chat_message.conversationId` (migration `drizzle/0004_harsh_king_cobra.sql`) and per-conversation trace grouping. The History action resumes older conversations (`+page.svelte:162`).
- **`trace_session` is described as append-only** (`frontend/README.md:141`), but a capture can be deleted: `deleteTraceSession` is wired to a `delete` form action on the list page (`src/routes/dashboard/traces/+page.server.ts:35-42`) and on the detail page (`src/routes/dashboard/traces/[id]/+page.server.ts:65`), both reachable from the UI.
- **Route table is incomplete in a way that hides real surfaces** (`frontend/README.md:34-49`). It omits `/dashboard/uploads`, `/dashboard/skills`, `/dashboard/settings`, `/api/chat/new-session`, `/api/chat/switch-session`, `/api/artifact`, `/api/marketplace` (+ `install`, `verify`), `/api/providers/config`, `/api/trace-entry` and the `/demo/*` scaffolding — all present under `frontend/src/routes`.
- **"Documents are text only" is false** (`frontend/README.md:186`). `readUpload` accepts any file (`src/routes/dashboard/documents/+page.server.ts:94-108`), the document page renders a `/text` preview for PDFs, and the agent derives PDF text at ingest (`agent/ingest.ts`). Only the 10 MB cap claim holds (`src/lib/server/upload-limit.ts:10`, `agent/corpus.ts:20`).
- **Chat bridge chunk list is incomplete** (`frontend/README.md:116-117`): the stream also emits `start-step`, `text-start`, `finish-step`, `data-artifacts` and `data-waking` (`src/routes/api/chat/+server.ts:123,215-224` and the waking timer). `data-artifacts` is load-bearing: the download buttons read it.
- **Setup path cannot bring the control plane up** (`frontend/README.md:52-59`): `cd .. && docker compose up -d --build` with the root `.env.example` default (`MANAGER_TOKEN=dev-manager-token`) or with no `.env` at all (compose interpolates the same default, `docker-compose.yml:9,41`) makes the manager refuse to boot (`enforce_token_default`). The documented sequence never generates a token, so "Create an account at `/login`. The first dashboard request provisions a sandbox" cannot happen from a fresh clone; `./dev.sh up` / `verify.sh` are the only paths that create one.

## marketplace/README.md

- **"The bundle never executes anywhere: the only interpreter is the model deciding to follow `SKILL.md`" is false** (`marketplace/README.md:53-55`). The skills instruct the model to run bundled helpers: `node skills/md-to-docx/references/logo-palette.js` (`marketplace/skills/md-to-docx/SKILL.md:103`) and `node /workspace/skills/pdf-text-extraction/references/extract-pdf.cjs` (`marketplace/skills/pdf-text-extraction/SKILL.md:44`); the review checklist's "bounded helpers … pure Node on core modules only" (`marketplace/README.md:66-68`) presupposes exactly that. What is true is that *installing* never executes anything — the sentence overstates it.
- **`requires.nodeLibraries` is documented as gate-enforced, but no gate reads it** (`marketplace/README.md:36-40`). The field is only round-tripped by `marketplace/manifest.mjs:84` and displayed by `frontend/src/lib/server/marketplace.ts:67`; `verify.sh:96` hardcodes `require('docx'); require('unpdf')`, and `e2e-test/skills.sh` covers only the two shipped bundles. A catalog entry declaring a library the image lacks would pass `manifest.mjs --check`, install, and verify by hash; the "if a skill needs a library the image lacks, `verify.sh` fails and the skill does not ship" claim depends on a human extending `skills.sh`, which is not a gate.
